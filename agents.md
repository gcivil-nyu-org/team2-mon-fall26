# Project progress and handoff

Read [docs/PROGRESS.md](docs/PROGRESS.md) before starting work. It records the current implementation status of the Epics and User Stories, outstanding work, and the next development steps. Read README.md for project context and setup.

Update docs/PROGRESS.md whenever a meaningful implementation, validation, or scope change is completed:

- Update the affected Epic/Story rows to match the actual code and verified behavior.
- Record what remains incomplete, any concrete blockers, and the next action or existing owner.
- Append a dated entry to the development archive describing what changed and what was verified. Preserve earlier entries so the project's progress remains available for later handoffs.
- Distinguish implemented code, acceptance verification, and GitHub/ZenHub workflow state. An open issue can have implemented code; closing a duplicate issue does not mean a feature was delivered.
- Record only checks that were actually run. Do not claim an entire Epic is complete when its remaining stories or acceptance checks are unfinished.

Use English in project code, documentation, and the product interface. Preserve the agreed scope boundaries: E01 displays hotspot information and existing reviews; E03 owns hotspot rating/review contributions; E08 owns discussions; E05 owns shared content reporting and moderation.
